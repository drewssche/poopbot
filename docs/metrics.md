# Metrics Semantics

Дата актуализации: 2026-10-19

## Базовые сущности

- `SessionUserState`:
  - дневной факт активности пользователя в конкретной сессии чата (`poops_n`),
  - в chat-local логике означает только состояние внутри конкретного чата за конкретную дату.
- `PoopEvent`:
  - детальные события походов внутри дня (`event_n`, `origin_chat_id`, bristol/feeling),
  - источник количества, участников, рекордов и распределений внутри чата и в рейтинге чатов;
  - локальное событие: `origin_chat_id == sessions.chat_id`.

## Время события и восстановления

- `created_at` — когда запись появилась в базе; `occurred_at` — известное время отметки (UTC).
- Новая обычная отметка: `source=recorded`, `occurred_at` заполнено.
- Восстановление периода: `source=restore`; «Забыл отметиться»: `source=late`;
  дополнение недостающей детализации счётчика: `source=reconciled`.
  У этих событий `occurred_at=NULL`: время нажатия не выдаётся за время события прошлого дня.
- Все эти события учитываются в количествах и стриках, но без известного времени не входят в слоты и титулы по времени суток.
- Локальные слоты используют часовой пояс чата. Глобальный ритм использует общий пояс `Europe/Minsk`.
- У старых записей `source=NULL`; до отдельной сверки сохраняется прежняя интерпретация `created_at` как времени события.
  Миграция добавляет nullable-поля и не переписывает историю.

## Стрики

- `Чатовый стрик`:
  - считается по локальным `PoopEvent` этого чата (`origin_chat_id == chat_id`).
- `Глобальный стрик`:
  - считается по `SessionUserState.poops_n > 0` по всем чатам пользователя.
  - день активен, если каноническое значение пользователя за дату (`max(poops_n)` среди чатов) больше нуля.

## /stats

- `🙋 Моя`:
  - итоги: дедуп по дням между чатами (`max(poops_n)` на `(user, day)`),
  - стрики: глобальные по `SessionUserState`.
  - блок `🕐 Твой ритм`: считается по каноническому чату дня, чтобы не раздувать слоты межчатовыми дублями.
- `💬 В этой личке`:
  - итоги и стрики считаются по локальным `PoopEvent` этой лички (`origin_chat_id == chat_id`) для консистентности блока.
  - `Ритм` и титул считаются только по реальным timestamps локальных `PoopEvent`.
- `👥 В этом чате`:
  - итоги/распределения: по `PoopEvent` этого чата (`origin_chat_id == chat_id`),
  - стрики: по локальным `PoopEvent` этого чата.
- `🌍 Глобальная`:
  - итоги: дедуп по дням между чатами (`max(poops_n)` на `(user, day)`),
  - глобальные стрики: по `SessionUserState` по всем чатам,
  - блок времени суток использует только события с известным временем из канонического чата дня.
- `🏟️ Среди чатов`:
  - `Топ по общему количеству`: число локальных `PoopEvent` по сессиям чата,
  - `Топ по среднему на участника`: total / число уникальных пользователей с локальными событиями,
  - `Топ по стрику чата`: максимум чатового стрика участников (по локальным `PoopEvent`),
  - `Рекорд дня`: максимум дневного количества локальных событий; при ничьей выводятся все чаты-победители.
  - место чата в его собственной статистике использует тот же подсчёт.

## Сверка старых данных

`python -m scripts.preview_data_reconciliation SNAPSHOT --date YYYY-MM-DD --output DIR`
создаёт JSON-план и HTML-отчёт из локального снимка. Подключения к БД и режима применения у команды нет.
В отчёте разделены эффект нового расчёта и прогноз отдельного исправления истории.
Положительные старые счётчики без событий предлагается дополнить событиями `legacy_import` без времени;
подтверждённые восстановления — пометить `legacy_restore` без времени.
Межчатовые копии предлагаются к удалению только с найденным оригиналом и совпадающими уточнениями;
неоднозначные записи остаются для ручного разбора. Перед применением нужны согласование плана,
резервная копия и повторная сверка исходных значений.

## Семантика без дублей

- Отметка в личке не делает пользователя отметившимся в группе.
- Отметка в группе не переносится в личку.
- Chat-local UI, напоминания и стрики живут только на локальных `PoopEvent` (`origin_chat_id == chat_id`).
- Глобальные totals и глобальный ритм используют антидубль-эвристику:
  - за день выбирается канонический чат пользователя,
  - канонический чат = чат с максимальным `poops_n` за дату,
  - при равенстве берётся более поздняя сессия.

## Период "за всё время"

- Старт диапазона: минимальная дата в `sessions` (дата старта данных бота).
- Для чата: минимальная дата `sessions` именно этого `chat_id`.

## Debug

- `/debug -> Stats raw` показывает:
  - origin-дни (`PoopEvent` с `origin_chat_id == chat_id`),
  - chat-state дни (`SessionUserState` в чате),
  - global-state дни (`SessionUserState` по всем чатам),
  - текущий/лучший стрик по каждому набору.

## Титулы по времени суток

- Слотный титул даётся, если:
  - все отметки попали в один слот, даже при малом количестве событий;
  - либо есть явный лидер по слоту при достаточном объёме данных.
- Если данных мало и они размазаны по разным слотам, титул не показывается.
- Если все 4 слота почти равны, используется отдельный титул `Круглосуточный серун`.
